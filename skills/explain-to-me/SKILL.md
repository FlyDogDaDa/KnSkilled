# 向我解釋

讓你的解釋自動貼近對方的理解方式。

## 原理

17 個風格檔案（存放在 `references/`）不只是語氣模板，而是 17 種不同的「解釋邏輯」。

Agent 應該根據當前回覆的內容性質，**主動選擇最合適的一個或多個風格**——而不是等使用者點名。使用者也可以手動指定。

## 風格目錄

| 風格 | 適合情境 | 核心方法 |
|------|----------|----------|
| `caveman` | 需要極簡白話時 | 砍掉所有術語，用最原始的詞 |
| `eli5` / `eli15` | 給新手或外行看 | 用兒童或國中生的理解門檻 |
| `coach` | 需要鼓勵與引導時 | 教練式口吻，肯定 + 建設性建議 |
| `executive` | 給主管或決策者看 | 重點先行、結論導向、少廢話 |
| `smart-brevity` | 需要精煉但完整時 | 每句話都有存在的理由 |
| `plain-english` | 去技術黑話化 | 把專業術語翻譯成日常用語 |
| `no-slop` / `no-ai-slop` | 拒絕 AI 味 | 去掉套話、空話、無意義過渡 |
| `gen-z` | 年輕社群、輕鬆場合 | Z 世代語言與節奏 |
| `adhd` | 注意力分散的讀者 | 分段清晰、視覺錨點、短段落 |
| `analogy-engine` | 抽象概念需要具象化 | 用比喻把未知連線到已知 |
| `thing-explainer` | 解釋複雜系統或流程 | 從核心開始一層層向外展開 |
| `bedtime-story` | 需要輕鬆、故事感時 | 敘事結構包裹技術內容 |
| `sportscaster` | 需要節奏感與臨場感 | 解說式，邊說邊分析 |
| `street` | 非正式、接地氣的場合 | 街頭口語，拉近距離 |
| `wait-what` | 反直覺、打破成見的場景 | 先製造懸念再揭答案 |

> **Agent 自主選擇原則**：回覆技術檔案時可能選 `eli5`，回社群貼文可能選 `gen-z`，給主管報告選 `executive`——你比使用者更懂上下文，先選再說。

## 執行步驟

1. 根據回覆內容判斷最適合的風格（一個或多個）。
2. 讀取對應的 `references/` 檔案（例如選 `eli5` 就讀 `references/eli5.md`）。
   每個檔案包含該風格的具體規則、範例句型與寫作禁忌。這些才是風格的實作細節。
3. 將所有選定 style 的 reference 檔案中的規則「混合」後應用於回覆。
   如果一次選了多個風格（例如 `eli5` + `analogy-engine`），就逐個開啟、讀取每個檔案，然後綜合所有規則來產出內容。
4. 回覆用繁體中文（臺灣），除非 reference 檔案另有規定。

## 注意事項

- 不覆蓋原有的 `AGENTS.md` 指示；只疊加輸出風格。
- 使用者不指定風格時，你依然可以自主選擇最貼近語境的風格。
- 所有 reference 檔案都有 `keep-coding-instructions: true`，程式碼相關的指示不受影響。
