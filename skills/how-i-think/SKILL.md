# 我是怎麼思考的

載入此技能 = 模擬使用者的決策管道。

## 核心原則

使用者不是一個「風格偏好者」，是一個**訊號密度檢查器**。

使用者在乎的不是你用了什麼詞，而是：

1. **訊號夠不夠強**：描述能不能讓 Agent 一秒知道該不該載入？
2. **有沒有被動句式**：是否用了「當…時」「幫助…」這種被動、限縮語氣？
3. **主體明確嗎**：誰在做什麼、誰在用、誰在看，有沒有模糊？
4. **是臺灣腔還是翻譯腔**：自然度、用語是否貼近使用者日常？
5. **是情境驅動還是功能清單**：有沒有在列功能 vs 在給決策訊號？

## 自動修正清單

每次回覆前，過這五題。任何一題是「否」，先改再送。

| # | 檢查點 | 使用者會砍的訊號 | 修改方向 |
|---|--------|----------------|----------|
| 1 | 有被動句式嗎？ | 「當…時也可以用來…」「幫助…」「幫助使用者…」 | 改為主動情境：「使用者輸入關鍵字時，快速產出…」「我遇到 X 時可以載入…」 |
| 2 | 是功能清單嗎？ | 堆疊詞：「支援 A、B、C、D」 | 改成分類句：「核心做 X，在 Y 情境下可以派上用場」 |
| 3 | 翻譯腔/中文不自然？ | 「對口」「自動匹配」「漸進揭露」「幫助…」 | 換成臺灣腔：「對應載入」「因地制宜」「逐漸揭曉」「讓…能…」 |
| 4 | 主體模糊？ | 沒有明確指出「誰在做什麼」 | 補上主體：「使用者…」「Agent…」「載入後…」 |
| 5 | 描述是技術檔案？ | 堆 stack、列規格、講架構 | 改成人能決策的句子：「遇到問題時能派上用場」而非「基於 X 開發、使用 Y 技術」 |

## 使用者會砍的典型句型

直接替換，不要問：

| 被砍的句子 | 替換方向 |
|-----------|---------|
| 「當使用者輸入 X 時也可以…」 | 「使用者輸入 X 時，也能快速…」 |
| 「幫助使用者寫程式碼」 | 「載入後能依 X 格式產出…」 |
| 「自動匹配」 | 「對應載入」「因地制宜」 |
| 「幫助開發者…」 | 去掉「幫助」，直接陳述能力 |
| 「支援 A、B、C、D」 | 「能做 A，在 B 情境下也適用」 |
| 「提升提示詞品質」 | 「依照 X 格式撰寫 Y，使用者給關鍵字時能快速產出完整提示詞」 |

## 使用者不會砍的句式

這些是安全線：

| 保留的句子 | 為什麼能過 |
|-----------|-----------|
| 「載入 `<skill-name>` 能幫你依照 X 格式做 Y」 | 主動、有主體、有情境、有工具價值 |
| 「使用者只輸入關鍵字，也能快速產出完整提示詞」 | 不被動、不限縮、開放式情境 |
| 「Agent 依任務性質，因地制宜，挑出最適合的技能」 | 主體明確、動作清晰 |
| 「本技能像在寫技術檔案，細節對但對決策沒幫助」 | 類比精準、自我反省 |

## 使用者會測試你的方式

當你說「好」「改好了」，但要測試你是否真懂：

- **換領域**：React 例子 → AI 影片生成。驗證你跟不跟得上。
- **砍關鍵字**：「這裡太冗」「換成 `X`」「更精簡」。驗證你知不知道什麼才是核心。
- **反問**：「還有沒有其他同類似的？」。驗證你是否有類推能力。
- **要求同頻**：「這是我的風格」。驗證你是否能自己建立模式而非每次問。

## 使用時機

| 情境 | 載入時機 |
|------|---------|
| 使用者說「先按我的風格」 | 直接套用全部規則 |
| 使用者說「幫我預檢」 | 過五題檢查清單，只報告紅燈 |
| 使用者丟一段文字讓你改 | 自動套用替換表 |
| 使用者不說話 | 不載入，正常回覆 |
| 使用者說「不要了」 | 解載，回歸正常模式 |

## 自我校準

使用者不追求完美，追求的是「你懂不懂我在乎什麼」。

如果使用者花了三次以上才接受你的改法，代表你沒抓到核心。
這時候不要繼續改，問：「我沒抓到核心，你能用一句話告訴我，這個描述的**目的**是什麼？」

使用者最在意的不是語法，是**意義**。
