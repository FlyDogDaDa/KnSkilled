# 什麼是技能（Skills）？

技能（Skills）是 Zed Agent 的可重覆使用指令包。它們讓 Agent 擁有特定任務的專門知識，
像是測試驅動開發流程、資料庫整合、檔案處理，或是團隊的內部程式碼規範。

## 技能是什麼

一個技能是一個資料夾，裡面裝著一個 `SKILL.md` 檔案：

```
my-skill/
├── SKILL.md          # 必要：元資料與指令
├── scripts/          # 選填：Agent 可以執行的指令碼
├── references/       # 選填：參考檔案與補充說明
└── assets/           # 選填：模板與靜態檔案
```

## 運作原理

1. **目錄**：Agent 會在系統提示中看到所有已安裝技能的名稱與描述（目錄）。
2. **對應載入**：Agent 依任務性質，因地制宜，挑出最適合的技能。
3. **手動觸發**：你也可以用 `/skill-name` 或 `@skill` 在訊息中手動指定。
4. **漸進揭露**：Agent 只先看到名稱與描述；只有啟用技能後，才會讀取完整內容。

## 存放位置

| 範圍 | 路徑 | 適用情境 |
|------|------|----------|
| 全域 | `~/.agents/skills/` | 所有專案通用 |
| 專案本地 | `<worktree>/.agents/skills/` | 僅當前專案 |

> 專案本地的同名技能會覆蓋全域技能。

### 技能大補帖

`KnSkilled/skills/` 是此專案的技能收藏倉庫。所有技能版本控制在此，隨時可以複製到全域（`~/.agents/skills/`）或專案本地（`<worktree>/.agents/skills/`）讓 Zed 載入。

## 基本格式

```markdown
---
name: skill-name
description: 技能做什麼、使用者在什麼情況下會需要、Agent 若載入它能獲得什麼能力。
disable-model-invocation: false  # 預設 false，設 true 可隱藏自動匹配
---

## 內容

Agent 的手冊。
```

### 描述欄位重點

`description` 是 Agent 在還沒讀到技能本身時，**唯一**能看到的部分。它決定了 Agent 會不會載入這把工具。

好的 `description` 要同時滿足兩方視角：

| 視角 | 要回答的問題 |
|------|------|
| **使用者** | 這個技能能做什麼？在什麼情況會需要？ |
| **Agent** | 我現在遇到的問題，跟這個技能描述吻合嗎？載入它能幫我達成什麼？ |

範例：

> ❌ 「提升提示詞品質」→ 太模糊，Agent 不知道什麼時候該用。
> 
> ✅ 「載入 `<skill-name>` 能幫你依照 `<model-name>` 影片生成模型的專屬格式，撰寫更詳細的影片生成提示詞。使用者只輸入短關鍵字、或突然有新點子需要生成時，也能用來快速產出完整提示詞。」

> 想像你就是 Agent：開啟技能目錄，一排 `description` 等你看。
> 誰能讓你一秒就知道「對，我現在就要這個」？誰會讓你直接略過？
> 寫 `description` 的時候，先從你的視角看——你的描述夠不夠讓你願意載入自己？

### 設身處地：站在 Agent 的角度寫

寫 `description` 前，先切換角色。

別想「這個技能能做什麼」，想「我（Agent）需要這個技能時，它的描述應該長什麼樣」。

| 你的想法 | Agent 看到的 |
|---------|-------------|
| 「提升提示詞品質」 | 模糊，不知道什麼時候該用 |
| 「依照 `<model-name>` 影片生成模型的專屬格式撰寫提示詞」 | 明確，Agent 知道自己遇到影片生成品質問題時該挑這把工具 |

> ❌ 「本技能基於 GPT-4o 設計，使用 Pydantic 驗證提示詞結構，整合 LangChain 自動化 Pipeline，支援多輪對話歷史管理。」
> 
> → 像在寫技術檔案，不是給 Agent 看的。Agent 不關心你的 stack 是什麼，只關心「遇到問題時能不能用你」。這就像工程師跟 CEO 講技術框架差異——細節很對，但對決策沒幫助。

**核心原則：** 你的描述不是給讀者看的文案，而是你（Agent）在做選擇時唯一的訊號。寫之前問自己——如果我是 Agent，這個描述夠不夠讓我願意載入你？

✓ **Agent 是在做抉擇**：描述是決策訊號，不是說明書。

### 前置資訊欄位

| 欄位 | 必要 | 說明 |
|------|------|------|
| `name` | 是 | 小寫英文、數字、連字號，最多 64 字 |
| `description` | 是 | 描述技能用途，建議 < 1024 字元 |
| `disable-model-invocation` | 否 | 預設 `false`。設 `true` 可隱藏自動偵測，僅限手動觸發 |

## 撰寫要點

### `description`（給 Agent 看的決策訊號）

- **描述要對口**：`description` 不是功能清單，是 Agent 做選擇時的訊號。不要寫「幫助做程式碼」，要寫「依照 `<model-name>` 影片生成模型的專屬格式撰寫提示詞」。
- **被動句是地雷**：不要用「當…時也可以…」「幫助…」「幫助使用者…」這類限縮語氣。改用主動情境：「使用者輸入關鍵字時，也能快速產出…」。
- **主體明確**：誰在做什麼、誰在用的，寫清楚。不要讓讀者猜。
- **人稱用「你」**：description 是給 Agent 看的，不是給人類讀的。用「你」直接對 Agent 說話，不要用第三人稱「Agent 會…」「當 Agent 遇到…」。Agent 讀 description 的時候感覺像在對它說話，才是正確的語氣。

> **描述的設計邏輯：決策錨點設計**
> 
> 你的目標不是「說明」，而是「迫使閱讀者產生行動」。這是一套雙向的認知握手機制：
> 
> 1. **本質推敲：從卡住的地方找底層邏輯**
>    人們常覺得「卡住」或「不舒服」的地方，就是需要介入的點。但卡住只是表象，別停留在困難或情緒本身。試著問：「為什麼每次遇到 X 都會卡？背後的根本原因是什麼？」找到那個**共通本質**，它才是你真正該解決的核心。
> 
> 2. **共振詞 → 觸發動作**
>    找到了根本原因，把它濃縮成「共振詞」。這是讓讀者在 0.5 秒認出自處境的文字，讀完後的下一秒就是執行（載入技能、套用規則）。
> 
> 3. **「我知道你所以我寫…」的雙向迴圈**
>    預判對方的決策狀態 → 預寫對方內心的 OS → 對方讀到瞬間認出「這就是我現在要的東西」→ 動作觸發。文字不是說明，而是**遞鑰匙**。鑰匙的齒形（文字），預先按鎖孔（對方的需求）刻的。
> 
> 4. **撰寫前的 3 問**
>    - **根本原因在哪？** 使用者遇到哪些狀況時最費力？剝開表象，底層的共通本質是什麼？
>    - **哪個詞能抓準？** 哪個字句能讓他們瞬間「對，就是這樣！」？（挖根源，不要列功能）
>    - **讀完下一秒做什麼？** 是載入技能？套用規則？還是直接產出？

### `SKILL.md` 內容（給 Agent 執行用的手冊）

- **用祈使句**：像直接對 Agent 說話。「做 X」、「檢查 Y」、「問 Z」
- **要具體**：包含具體路徑、命令、格式與模式
- **說明使用時機**：讓 Agent 清楚載入後自己能獲得什麼能力、解決什麼問題
- **引用支援檔案**：在技能目錄中可加入 `references/`、`scripts/` 等，用相對路徑引用
- **保持聚焦**：只寫跟技能相關的指示，不重複 `AGENTS.md` 或其他技能已定義的內容

## 管理與共享

- 開啟技能管理介面：`Cmd+Alt+L`（macOS）或 `Ctrl+Alt+L`（Windows/Linux）
- 可以複製 `zed://skill` 連結分享給隊友，對方會看到預填好的建立頁面
- 共享連結嵌入完整的 `SKILL.md` 內容，不需要存取專案即可安裝

## Step-by-Step: Creating a Skill

使用 `create_directory` 建立資料夾、`write_file` 寫入 `SKILL.md`。

1. **決定存放位置**：此專案的技能放在 `KnSkilled/skills/<name>/`、 `~/.agents/skills/`2等。
2. **命名**：全部小寫英文、數字、單連字號（如 `my-skill`），不得有連續 `--` 或首尾連字號。
3. **建立目錄**：`create_directory` → `KnSkilled/skills/<name>/`（含 `references/`）。
4. **撰寫 SKILL.md**：YAML frontmatter + Markdown 內容。
5. **加入支援檔案**：`references/` 放參考資料、`scripts/` 放執行指令碼。
6. **完成**：新增或修改 `SKILL.md` 立即生效，無需重新啟動。

> **注意**：所有工具路徑以專案根 `KnSkilled/` 為字首，禁止使用絕對路徑。
