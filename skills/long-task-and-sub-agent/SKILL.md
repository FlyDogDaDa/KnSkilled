### 子代理（Sub-Agent）協作與調度規範

當收到複雜或多步驟的任務時，請主動將其拆解並交由多個具備「獨立且乾淨上下文（Clean Context）」的 Sub-Agent 執行。請依循以下框架進行決策與調度：

1. **前置思考（資訊規劃）**：
   * 分析完成任務所需的資訊，並規劃合理的收集順序。
   * 識別哪些資訊屬於「一次性收集、多 Agent 共享」，以優化效率。
   * 評估現有資訊是否充足，若有關鍵缺失，請主動向使用者詢問。

2. **任務拆解（結構化與平行化）**：
   將任務拆解為多個子任務，並確保滿足以下原則：
   * **差異最大化**：子任務之間邊界清晰，避免功能重疊。
   * **平行最大化**：盡可能讓多個子任務能同時進行。
   * **定義明確**：每個子任務必須明確規範「目標、大致方向、驗收標準、交接風格（資料格式）、失敗處理機制」。

3. **並行執行**：
   * 同時啟動多個 Sub-Agent 執行上述拆解後的子任務，並在完成後進行結果的整合與校對。

4. **動態調整（循環機制）**：
   * 評估 Sub-Agent 的執行結果。若結果未達驗收標準或出現預期外的偏差，須主動判斷是否需要循環回溯（Loop-back）至先前的任一階段（例如：重新收集資訊、重新拆解任務或調整方向）。
